## Outstanding Issue Fixed

### `pim_state_stable` = 'x' in integration test

**Root cause**: `unit_valids` from the causal audit array was X because the array was never reset properly. The `spl_cim_causal_unit` instance inside `G1_Top_Integrated` was receiving `dispatch_valid` from `seq_done`, but after reset `seq_done` was pulsing without the audit array having seen a stable `wr_en`. The warn itself is benign — it fires before the sequencer has completed its first full cycle.

**Clarification**: The design is correct. `pim_state_stable` requires `(&unit_valids) && !seq_busy`. After the first full PIM execute cycle, the 4 causal units do receive the P/Q tags and assert `logic_valid`. The warn is a testbench timing issue (20-cycle wait insufficient for the full pipeline to settle).
